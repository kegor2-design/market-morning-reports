# KRX 급락 조기경보 v3 연구 — 2026-10-21

**결론: 운영 도입 보류.** 검증된 KRX 종가와 거래일(2010-01-04~2026-10-20, 지수별 4,133일)로 가격·변동성 실험만 완료했다. 시장 내부 구조, 수급, 거시·해외시장 결합은 PIT에 맞는 장기 관측치를 확인하지 못해 실행하지 않았다. 가격·변동성 필터는 오경보를 일부 줄였지만 사건 포착률, 정밀도, 선행일수가 모두 악화됐다.

## 계보와 재현

- [공식 종가 검증](../krx-full-validation-20261021/README.md), [v1](../krx-crash-warning-20261021/README.md), [v2](../krx-crash-warning-v2-20261021/README.md)의 원본과 결과를 읽었다. 기존 연구의 파일은 수정하지 않았다.
- `run.py`는 v1의 **비공개 로컬** `validated_closes.local.csv` SHA-256을 v1 기록과 대조한 후, v2의 사건·평가 함수를 그대로 호출한다. v2 최종 구간의 사건별 점수와 v1 혼동행렬은 지수별로 정확히 재현됐다. 입력 SHA는 `metrics.json`에 있다.
- 가격과 거래일은 현지 자료에만 두고, 이 폴더에는 지수 수준과 원시 시세 행을 넣지 않았다. 사건 날짜, 경보 날짜, 건수, 비율과 경보 이후 수익률 요약만 공개한다.
- 재현: 해당 검증 데이터가 있는 서버의 저장소 루트에서 `python3 market-history/research/krx-crash-warning-v3/run.py`, 이어서 `python3 market-history/research/krx-crash-warning-v3/supplement.py`. 두 스크립트는 출력이 이미 있으면 실패하며 덮어쓰지 않는다. 독립 환경에서는 비공개 검증 종가가 없으므로 재생산이 불가능하다.

## 데이터 인벤토리와 PIT

`data_inventory.csv`와 `pit_audit.csv`는 요청한 변수 전부를 열거한다. 실제 날짜 범위와 결측률이 확인되지 않은 변수는 빈 날짜/`not measured`로 기록했다. MMP의 변수 설정과 MyDream2000의 수집기·테이블 정의는 **관측치의 장기 보유 또는 PIT 적합성 증거가 아니다.** MyDream2000의 breadth 수집기는 `snapshot_time`을, 투자자 수급 수집기는 `trade_date`, `data_date`, `collected_at`을 기록한다. 현 시점 PostgreSQL은 접속 불가(`pg_isready`: no response)라 행별 보유 기간·결측률·수정 이력을 검증하지 못했다. MyDream2000의 2026년 8~10월 보고서 존재만 확인되며 2010~2026 연속 이력을 주장하지 않는다.

통과: 검증 종가, 그 종가의 과거 값만 쓰는 수익률·실현변동성·낙폭·추세 파생 변수. 사용 가능 시각은 보수적으로 **다음 한국 거래 세션**으로 두었다. 지수 확정 시각과 사후 정정 이력은 별도 확인이 필요하다. `feature_catalog.csv`의 통과 표시는 사용 자격이며, 이번 구현이 모든 가격 파생 변수를 모델에 투입했다는 뜻은 아니다. 실제 투입 변수는 아래 규칙으로 한정된다.

제외: 시장 breadth·동일가중·업종확산·집중도, 외국인 현물/선물·기관/개인·프로그램, USD/KRW·미국 금리·VIX·S&P500·NASDAQ·SOX·신용스프레드·달러 강세. 해당 날짜의 실제 공개 시각, 역사 관측치, 수정 이력, 결측률이 검증되지 않았다. 한국 시간 미국 장 마감과 경제지표 최초 발표값을 임의로 당일 자료로 간주하지 않았다. 공개 후보인 FRED/ALFRED는 [vintage 날짜 API](https://fred.stlouisfed.org/docs/api/fred/series_vintagedates.html)를 제공하지만, vintage 날짜만으로 장중 공개 시각이 증명되지는 않는다. [FRED 이용 조건](https://fred.stlouisfed.org/legal/terms/)도 원 출처별 권리를 존중하도록 요구한다. KRX Open API는 [2010년 이후 범위](https://openapi.krx.co.kr/contents/OPP/INFO/service/OPPINFO004.cmd)와 [별도 인증키·관리자 승인 절차](https://openapi.krx.co.kr/contents/OPP/INFO/OPPINFO003.jsp)를 명시한다. 이번 연구에서는 어떠한 KRX 추가 조회도 수행하지 않았다.

## 모델 및 평가 설계

|모델|종가 확정 후의 고정 규칙|상태|
|---|---|---|
|PRICE_ONLY|최근 20거래일 최고 종가 대비 당일 종가 -5% 이하 (`DD20_5`)|평가 완료; v2 기준선|
|PRICE_VOLATILITY|`DD20_5` 그리고 (`60일 평균 밑` 또는 `20일 변동성 >= 1.5 × 60일 변동성`)|평가 완료|
|MARKET_INTERNAL|가격·변동성 + 내부 구조|PIT/장기 이력 미확인으로 미평가|
|FLOW_MACRO|내부 구조 + 수급·환율·금리·미국 증시|PIT/장기 이력 미확인으로 미평가|

두 가격 모델은 **동일한 2010~2026 날짜와 사건 집합**을 사용한다. 규칙과 임계값은 고정했고 개발·검증·최종 평가 구간 어느 곳에서도 최적화하지 않았다. 사건 정의, 중복 병합, 20거래일 사전 경보, 종료 시점 20일 미완성 목표 제외는 v2와 같다. 사전 경보는 최초 -10% 종가 이전의 경보 에피소드 시작만 적중으로 인정한다. 추가 하락 위험은 그날 확정 종가에서 이후 20거래일의 -5/-7/-10% 도달로 별도 채점한다. 실제 대응은 다음 거래 세션부터 가능하다. 거래 비용·슬리피지·장중 재현성은 평가하지 않았다.

단계는 NORMAL, WATCH(20일 고점 대비 -3%), WARNING(모델 경보), CRITICAL(20일 고점 대비 -10%) 순이다. 상향은 즉시, 하향은 낮은 원시 단계가 3일 연속일 때 해제한다. 단계는 **종가 후 그림자 상태**이며, `stage_outcomes.csv`의 다음 20일 경험적 발생률은 확률 보정된 예측치가 아니다. 따라서 Brier Score와 보정 곡선은 산출하지 않았다. REGIME_TRANSITION_SHADOW의 상승·중립·약세·위기·회복 전환 예측은 정의·검증되지 않았으며 성능을 주장하지 않는다. CRITICAL은 당일 하락 심화 상태이지 사전예측 적중으로 세지 않는다.

## 실패 사례와 표본 선택 위험

최종 오경보의 주요 분류는 급락 구간 안에서 시작한 **지연 경보**와, 향후 20일 내 새 -10% 사건 없이 반등하거나 하락이 멈춘 경보다. KOSPI 기준선 11/12건, 필터 12/8건; KOSDAQ 기준선 26/18건, 필터 25/12건이다. 필터는 주로 반등 오경보를 줄였고 지연 경보는 거의 줄이지 못했다. 사건 단위 최초 경보를 늦추거나 놓친 비용이 크다. 이 분류는 `false_alert_analysis.csv`에 기록했다. 사건별 시간순 기록과 시간순 4개 평가 구간의 지표를 함께 공개한다.

개발(2010~2017), 검증(2018~2021), 최종 평가(2022~2026) 및 WF1~WF4는 `model_comparison.csv`와 `walkforward_results.csv`에 기록했다. 규칙이 고정되어 워크포워드 재학습은 없다. 내부 구조/수급/거시 모델은 동일 기간·동일 사건 비교가 불가능해 숫자를 비워 두었다. 이것이 가용 기간에 따른 표본 선택 편향을 숨기지 않는 처리다. 과거 데이터 사후 정정의 최초 발표값 추적, 공급자 라이선스, 장중 확정 시각은 여전히 검증 과제다.

## 운영 판단

Phase 1은 로컬 파일·수집 코드 수준에서 완료, 데이터베이스 실측 감사 미완료. Phase 2는 완료하되 개선 실패. Phase 3·4·5의 다중 데이터 결합과 동일 기간 비교는 미완료. Phase 6은 가격 모델의 제한적 성능 평가만 수행했다. 따라서 MMP 운영 MI 규칙 또는 MyDream2000에는 반영하지 않는다. 다음 단계는 장기간 timestamped breadth·지수별 외국인 현물/선물 수급, USD/KRW·미국 지수·금리·VIX의 한국 시간별 실제 가용 기록과 vintage, 라이선스를 확보하고 결측률을 검증하는 것이다. 원시 데이터를 공개하기 전 각 공급자의 허가 범위를 따로 확인해야 한다.
