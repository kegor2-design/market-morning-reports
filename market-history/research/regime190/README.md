# Regime 190 historical data collection checkpoint

Target period: 2010-01-01 to 2026-10-27. KOSPI and KOSDAQ are separate. The exact export time and status counts are in `worker_progress.json`; `inventory_190.csv` has exactly 190 unique IDs. This is an **in-progress** checkpoint, not an all-data-acquired or collection-attempts-complete claim.

The latest bounded source-access pass linked all 20 previously unattempted IDs to an actual official request or local fallback check. Its `provider_probe_20.csv` labels landing/archive pages as access probes, never historical indicator observations. Eight official announcement archive pages were downloaded privately and remain unparsed raw inputs. A zero unattempted count does not mean their historical data or two independent sources were obtained.

The first audit verified two Naver Finance index XML files and normalized CSVs by SHA-256, with 4,133 target-window rows per market through 2026-10-20. Four existing monthly repository CSVs supply limited components. `derive_more.py` calculated 20 additional price indicator definitions for both markets into ignored private files; four price indicators remain open because the definition or causal display convention needs further verification. The complete 190-row audit records source and calculation gaps individually.

The independent `worker.py` uses a locked SQLite checkpoint in a private research directory. It reads the operating PostgreSQL database only inside `BEGIN READ ONLY` transactions with a statement timeout, and calls selected official FRED series through bounded, key-redacted HTTPS requests. FRED raw observations, DB query summaries, and computed series remain private. The public `worker_source_manifest.csv`, `worker_attempts.csv`, `worker_quality_report.csv`, and `worker_progress.json` contain metadata only. A candidate DB field is not considered acquired until its link to the indicator is checked. `schema_audit.md` supersedes the first audit's DB connection failure.

The resumed DB adapter now writes 2,497 separate, checksum-recorded per-symbol files for eight OHLCV indicators. An interrupted run resumes at the next unrecorded symbol, and the worker pauses the adapter below 5 GiB free space. Five short-history Korean rate indicators have a separate private derived file. `worker.py --status` reads the checkpoint without taking the worker lock or writing heartbeat files; `last_real_request_at`, `last_new_derived_at`, and the heartbeat are reported separately. `indicator_field_mapping.csv`, `provider_attempts.csv`, `data_coverage.csv`, and the 190-row `quality_report.csv` are conservative per-ID public metadata. The previous index-only quality table is retained as `index_quality_report.csv`.

Official endpoint documentation: [FRED observations](https://fred.stlouisfed.org/docs/api/fred/series_observations.html), [OpenDART company codes](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018), and [OpenDART financial statements](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020). The OpenDART full financial statement API documents coverage beginning in 2015, so it cannot supply the entire 2010–2014 target through that endpoint.

Every acquired source remains `PIT_UNVERIFIED` for final predictive use. FRED snapshots include current revised values; row-level release timing and historical vintages are not established. The index files lack row-level publication timestamps. Predictive walk-forward backtesting remains `NOT_RUN_PIT_GATE`. The 2010+ index OHLC audit had no invalid rows; five invalid rows occur before 2010. Exchange calendar and provider comparison still need independent verification.

## Reproduction and service

Set research-directory permissions first: `install -d -m 700 "$HOME/MyDream2000/research/regime190"`. Check status with `stock_env/bin/python market-history/research/regime190/worker.py --status`; this works while the service holds its execution lock. Run manual collection only when the service is stopped, using `--dry-run` before `--resume`. The installed user unit is `regime190-collection.service`; `systemd-analyze verify market-history/research/regime190/regime190-collection.service` passed. Service activation and linger require the server account's normal systemd permissions. The worker supports `--status`, `--resume`, `--max-runtime`, `--max-attempts-per-source`, and `--concurrency 1`. To export a safe metadata checkpoint, run `stock_env/bin/python market-history/research/regime190/export_worker.py`, then `stock_env/bin/python market-history/research/regime190/audit_190.py`.

The optional `regime190-publish.timer` checks every 30 minutes for **new checkpoint progress** and uses `publish_checkpoint.py` to fetch, compare, stage only approved metadata paths, scan for private markers, and push without force. It skips a dirty worktree or a remotely advanced branch; collection continues if publication fails. Check with `systemctl --user status regime190-collection.service regime190-publish.timer` and `journalctl --user -u regime190-collection.service -n 30`. Stop or resume only the research worker with `systemctl --user stop regime190-collection.service` or `systemctl --user start regime190-collection.service`. The timer can be stopped separately with `systemctl --user stop regime190-publish.timer`.

Remaining work includes indicator-specific DB field mapping, official/fallback adapters for the review queue, source rights, exact publication times and revisions, Korean trading-calendar reconciliation, and PIT-safe backtesting. The long-running worker does not turn unresolved provider mappings into a success status.
